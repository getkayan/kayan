# Per-package statement-coverage floors.
#
# CI fails when a package drops below its floor. The point is not to chase a
# number: it is to stop a package that was deliberately covered from quietly
# losing that coverage again. core/admin sat at 11.3% and core/audit at 13.0%
# while both gate security decisions, and nothing objected until somebody
# looked.
#
# Floors are set a couple of points below the coverage measured when they were
# recorded, so ordinary drift does not break the build while a real regression
# does. Raising a floor after improving a package is welcome. Lowering one is a
# deliberate act that belongs in its own commit with a reason.
#
# Format: <package path relative to the repo root> <minimum percent>
# A package with no entry here is reported but does not fail the build.
